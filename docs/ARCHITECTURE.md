# Архитектура OpenFrankenDriver

> Техническое руководство по внутреннему устройству, архитектуре инсталлятора NVIDIA NVI2, механизмам обхода ограничений и интеграции классической панели управления.

---

## 1. Аппаратный контекст: видеокарты-мутанты

### 1.1 Что такое видеокарта-«мутант»?
Видеокарты-мутанты (например, **RTX 3070m**, **RTX 3060m**, **RTX 2060m**, **GTX 1660m**) производятся на базе графических процессоров NVIDIA, изначально предназначенных для ноутбуков (мобильные кристаллы GA104, GA106, TU106 и др.). Китайские производители распаивают эти чипы и мобильную память GDDR6 на полноразмерные десктопные печатные платы с разъёмом PCI Express x16.

### 1.2 Причина «Ошибки 43» (Error 43) в официальном драйвере
Официальный драйвер NVIDIA при инициализации видеокарты проверяет её аппаратный контекст:
1. Идентификатор устройства (`DEV_249D` и др.) относится к мобильной линейке.
2. Однако физическая шина — полноразмерная десктопная PCIe без признаков мобильного хоста (отсутствует контроллер питания ноутбука, ACPI-таблицы мобильной платформы, модуль Optimus/MUX-switch).
3. При обнаружении несоответствия драйвер возвращает ошибку инициализации, и диспетчер устройств Windows выставляет **Код 43 (Это устройство было остановлено, поскольку оно сообщило о возникновении неполадок)**.

### 1.3 Аппаратный обход без модификации бинарных файлов ядра
В архитектуре драйвера NVIDIA предусмотрен специальный недокументированный диагностический флаг инициализации Resource Manager: `RM1457588`.
При установке значения:
```ini
HKR,,RM1457588,%REG_DWORD%,1
```
в разделах конфигурации реестра адаптера (`nv_miscBase_addreg__*`), драйвер `nvlddmkm.sys` игнорирует несовпадение платформы и корректно запускает устройство в полнофункциональном десктопном режиме WDDM.

## 2. Безопасность и совместимость с античитами (WHQL Integrity)

Ключевой принцип OpenFrankenDriver: **Ни один исполняемый файл ядра (`nvlddmkm.sys`, драйверы DirectX, Vulkan, CUDA, OpenCL) не модифицируется и не патчится**.

- **Файлы ядра**: Сохраняют оригинальную цифровую подпись корпорации Microsoft (WHQL) и NVIDIA.
- **Безопасный режим Windows**: Система работает с параметром `testsigning No`. Не требуется включать тестовый режим загрузки ОС или отключать проверку подписей (`bcdedit /set nointegritychecks on` **НЕ используется**).
- **Античиты**: Игровые античиты уровня ядра (**Easy Anti-Cheat**, **BattlEye**, **Vanguard**, **Valve Anti-Cheat / CS2**, **FaceIT**) проверяют цифровую подпись бинарников ядра в оперативной памяти. Поскольку бинарники оригинальные, античиты работают штатно и без блокировок.
- **Каталог безопасности (`nv_disp.cat`)**: Из-за изменения `nv_dispi.inf` генерируется собственный рекурсивный каталог Microsoft Security Catalog по всем 271 файлам драйвера через системную утилиту `makecat.exe` и подписывается сертификатом со штампом времени RFC3161 DigiCert. Каталог дублируется в каталог `EACSupport` инсталлятора.

## 3. Автоматический импорт сертификата (Zero-Touch)

В оригинальном драйвере FrankenDriver при установке на чистую систему всплывало предупреждающее окно Windows Security красного цвета («Windows не может проверить издателя этого драйвера»), требующее ручного подтверждения или предварительной ручной установки сертификата через оснастку `certmgr.msc`.

В OpenFrankenDriver реализован нативный механизм автоматической регистрации доверия:
1. В манифесте `setup.cfg` объявлен скрытый критический субпакет:
   ```xml
   <sub-package name="FrankenDriverCert" disposition="critical" hidden="true" />
   ```
2. Основной видеодрайвер имеет зависимость от этого пакета:
   ```xml
   <sub-package name="Display.Driver" disposition="critical">
       <dependencies>
           <package package="FrankenDriverCert" type="after" />
           <package package="EACSupportCatalog" type="after" />
       </dependencies>
   ```
3. Сценарий `FrankenDriver.nvi` вызывает системную утилиту Windows `certutil.exe` и регистрирует открытый ключ сертификата в трёх локальных хранилищах компьютера:
   - `Root` (Доверенные корневые центры сертификации);
   - `CA` (Промежуточные центры сертификации);
   - `TrustedPublisher` (Доверенные издатели).
4. В результате Windows считает инсталлятор и все связанные компоненты доверенными: установка проходит **в один клик без единого предупреждения**.

## 4. Проблема DCH и восстановление Классической Панели Управления

### 4.1 Почему в современных драйверах нет панели управления?
Начиная с драйверов DCH (с 2018 года), NVIDIA перевела панель управления в формат UWP-приложения из Microsoft Store.
1. В инсталляторах ветки 620+ шаг авторазвёртывания панели через DISM заблокирован флагом:
   ```xml
   condition="!IsNvCplUIPresent &amp;&amp; Feature.NvCpl"
   ```
   где `Feature.NvCpl = false`, так как NVIDIA форсирует переход на «NVIDIA App».
2. На облегчённых сборках Windows (Windows 10/11 LTSC, сборки Flibustier Compact, AtlasOS, ReviOS) Microsoft Store вырезан или отключён. Пользователь остаётся без интерфейса настройки разрешения, частоты обновления, цветового диапазона и G-Sync/FreeSync.

### 4.2 Скрытый механизм чистки NVIDIA (`removeCPLInstallData`)
При анализе журнала NTFS (USN Journal) было обнаружено, что видеодрайвер NVIDIA содержит фазу удаления:
```xml
<custom phase="removeCPLInstallData" action="removeCPLInstallData" when="install"/>
```
Библиотека `DisplayDriverExt.dll` принудительно стирает файлы `nvcplui.exe` и `nvcpluir.dll` из директории `Program Files\NVIDIA Corporation\Control Panel Client\` спустя ровно 4 секунды после распаковки.

### 4.3 Решение в OpenFrankenDriver
1. В `DisplayDriver.nvi` строка вызова `removeCPLInstallData` нейтрализована (закомментирована).
2. Создан независимый субпакет `Display.NVCPL`, содержащий Win32-бинарники, извлечённые из заводского пакета NVIDIA:
   - `nvcplui.exe` — исполняемый файл Панели управления;
   - `nvcpluir.dll` — библиотека локализации и интерфейсных ресурсов (включая русский язык);
   - `nvImage.dll` — графический рендерер панели;
   - `NvGpuUtilization.exe` — модуль мониторинга загрузки ГП.
3. Развёртывание выполняется нативной C-утилитой `install_helper.exe` на фазе `when="installClose"` — строго после того, как все компоненты NVIDIA завершили работу.
4. Создаются корректные ANSI/Unicode ярлыки `NVIDIA Control Panel.lnk` на Рабочем столе и в Меню «Пуск», регистрируется пункт контекстного меню рабочего стола и прописывается флаг:
   ```ini
   HKLM\SOFTWARE\NVIDIA Corporation\Global\NVTweak -> EnableNvcplUIOnDCH = 1
   ```

## 5. Монолитный SFX и PE-структура инсталлятора

Инсталлятор NVIDIA представляет собой самораспаковывающийся исполняемый файл (SFX), состоящий из:
- PE-заголовка и распаковщика `PackageLauncher.exe` (1 118 720 байт);
- Конфигурационного блока параметров распаковки (1 572 байта);
- Архива 7-Zip (LZMA2).

### 5.1 Обход ошибки `0xc0000005`
При модификации SFX оригинальная цифровая подпись NVIDIA в конце файла аннулируется. Если не занулить указатель на таблицу сертификатов в PE-заголовке, загрузчик Windows пытается прочесть несуществующую структуру безопасности по старому смещению и падает с исключением `STATUS_ACCESS_VIOLATION (0xc0000005)`.
Скрипт сборки использует библиотеку `pefile` для корректного обнуления записи `IMAGE_DIRECTORY_ENTRY_SECURITY` в `OPTIONAL_HEADER`:
```python
pe = pefile.PE(data=pe_bytes)
sec_idx = pefile.DIRECTORY_ENTRY['IMAGE_DIRECTORY_ENTRY_SECURITY']
pe.OPTIONAL_HEADER.DATA_DIRECTORY[sec_idx].VirtualAddress = 0
pe.OPTIONAL_HEADER.DATA_DIRECTORY[sec_idx].Size = 0
```

### 5.2 Совместимость со старым распаковщиком NVIDIA
`PackageLauncher.exe` не поддерживает современные алгоритмы сжатия исполняемых файлов 7-Zip (BCJ2, фильтры ARM64). Для стабильной распаковки упаковщик 7-Zip вызывается со строгим флагом `-mf=off`:
```cmd
7z.exe a payload.7z <files> -m0=LZMA2:d26 -mf=off -mx=9 -ms=on -mmt=16
```
После склейки готовый бинарник подписывается локальным сертификатом со штампом времени DigiCert RFC3161.
